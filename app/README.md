# vault_app（保管庫のファイルブラウザ。Phase 0・Windows）

保管庫を開いて、ファイルを見て・作って・消して（ゴミ箱へ）・戻すアプリです。表示と入力だけを受け持ち、
ロジックは Rust のコア（`crates/vault-ffi` → `vault-core`）にあります。

## ビルドと起動

リポジトリの根で：

```sh
cargo build --release -p vault-ffi      # vault_ffi.dll を作る（アプリのビルドより先に）
cd app
flutter run -d windows                  # 開発のとき
flutter build windows                   # build/windows/x64/runner/Release/ に exe と vault_ffi.dll ができる
```

`app/windows/CMakeLists.txt` が、`target/release/vault_ffi.dll` を exe の隣へ写します（なければビルドが止まります）。

**注意**：アプリは起動のたびに、その PC のホームの直下に既定の保管庫 `Buildoffice`（`%USERPROFILE%\Buildoffice`）を
作って開きます（なければ作る）。`flutter run` や、作った exe の起動も同じなので、**開発の PC で起動すると、開発の PC の
ホームに `Buildoffice` ができます**。要らなければ、アプリを閉じてから消します（消しても、次の起動でまた作ります）。
`flutter test` は本物のホームに作りません（既定の保管庫を開く関数は偽物に差し替え、結合テストも形の誤りの要求だけを送ります）。

## テスト

```sh
flutter analyze
VAULT_FFI_REQUIRED=1 flutter test   # release の vault_ffi.dll を呼ぶ結合テストを含む
```

`VAULT_FFI_REQUIRED=1` を付けると、DLL がないときに結合テストを飛ばさずに失敗にします（確かめや CI では、これを付けて流します）。
付けなければ、DLL がないときは、結合テストを理由付きで飛ばします。

## 使い方

- 起動すると、既定の保管庫（ホームのフォルダの中の `Buildoffice`）を開きます。なければ作り、「保管庫を作った
  （ホームのフォルダの中の Buildoffice）」と知らせます。開けないとき（`Buildoffice` が保管庫でないフォルダ・ファイル・
  リンクのときなど）は、作らずに、いちばん上のカード「既定の保管庫」に理由を出します。名前を変えるか除けてから、
  「既定の保管庫を開く」を押します。保管庫を閉じて戻ったときは、自動では開き直しません（このボタンで開きます）。
- 既定の保管庫を消すと、次の起動で空の保管庫を作り直します。
- ほかの保管庫を作るときは、下のカード「新しく作る」で、置き場所（「選ぶ…」で選ぶか、絶対パスを入れる。例：`D:\Vaults`）と
  保管庫の名前（例：`MyVault`）を入れて「作って開く」。置き場所の中に、その名前のフォルダを作って開きます。
  置き場所は、すでにあるフォルダにします（ないときは、何も作らずに断ります）。
- 次からは、上のカード「保管庫を開く」で、保管庫のフォルダ（例：`D:\Vaults\MyVault`）を「選ぶ…」で選ぶか
  絶対パスを入れて「開く」。パスは覚えないので、開くたびに選びます。
- フォルダを選ぶ窓は OS の標準の窓です（Windows の runner が出します）。
- 消したものはゴミ箱（右上）から戻せます。
- アプリが前面にあるあいだ、ほかのアプリでの変更を調べて一覧を新しくします（右上の「更新」でも調べます）。
  間隔は 5 秒を基本に、前の調べにかかった時間に合わせて延ばします。
- 読み取り専用で開いても、変更の検知（rescan）は、保管庫の `.vault` の索引と履歴を更新します（vault-core の仕様）。
  作る・消すのボタンは出ず、ゴミ箱の「戻す」は押せません。
